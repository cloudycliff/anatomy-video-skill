# Anatomy explainer video

This skill orchestrates three installed skills and adds the parts they don't cover:
- **`/hyperframes`** handles intent, brief and project rules.
- **`/faceless-explainer`** provides the step order, gates, audio, captions, transitions and render.
- **`/anatomy`** supplies the isometric craft: camera, four-tone light, painter's order, cutaways.

Read their SKILL.md files when a step below says so. Don't restate their rules here.

## The one idea that matters

**One rig, many states.** The whole video is a single parametric drawing of the device. Each frame
is that rig seen through a camera, with a state that is a pure function of time and cued to the narration's
phrase starts. This gives:
- perfect continuity between frames;
- seek-safe rendering;
- one place to fix drawing bugs.

It is also why frames are **generated by one script from specs** (`tools/frames/build.mjs`) instead of
being dispatched to one sub-agent per frame, as faceless-explainer Step 5 does.

Worked example (59 s, 9:16, Mandarin, 7 frames): `examples/speaker/`. Read `examples/speaker/README.md` first.

## Workflow

Copy this checklist and track it:

```
- [ ] 0  Brief + project      (hyperframes intent layer → faceless-explainer Step 0)
- [ ] 1  Teaching chain        (physics truth before any drawing)
- [ ] 2  Design + fonts        (preset + stage-fonts + cjk-fonts)
- [ ] 3  Storyboard + script   (one rig state change per frame)
- [ ] 4  Voice + timings       (zh-voice.mjs → sync-durations)
- [ ] 5  Rig                   (templates/rig.js → preview sheet verified)
- [ ] 6  Frames                (specs in build.mjs, cues from audio_meta.json)
- [ ] 7  Rebuild + verify      (rebuild.mjs → lint → snapshot → check)
- [ ] 8  Preview, one question, render, deliver
```

`<skill>` below means this skill's directory. Run every command from `videos/<project>/`.

### 0 · Brief and project

Follow `/faceless-explainer` Step 0 exactly: route through `/hyperframes` intent, `init`, write `BRIEF.md`,
record preferences, and show auth status. The defaults when the user doesn't say:
- 9:16 at 1080×1920;
- voiceover plus captions;
- anatomy light theme;
- preset `code-editorial`;
- no BGM;
- about 60 s.

In autonomous mode, post heads-up summaries and ask only the final render question.

### 1 · Teaching chain

Before writing anything visual, write the causal chain as 5–8 links, each one a visible change in the
object. For the speaker: current → coil in the magnetic gap → force F = B·I·L → cone moves → suspension
recentres → air compressions and rarefactions → frequency and amplitude map to pitch and loudness. For each link:
- note the real numbers (dimensions, field strength, forces) so the cards can show plausible values;
- note which part must be **lit** and what **motion** proves the link.

Drop links that no motion can show.

### 2 · Design and fonts

```bash
node <faceless-explainer>/scripts/build-frame.mjs --preset code-editorial --hyperframes .
node <skill>/scripts/stage-fonts.mjs --preset code-editorial
node <skill>/scripts/cjk-fonts.mjs          # Chinese only; rerun after any copy change
```

### 3 · Storyboard and script

Write `STORYBOARD.md` and `SCRIPT.md` per faceless-explainer Step 3 and Step 4, with these differences:

- **One frame = one link of the chain = one rig state change.** Typical frame patterns from the example:

  | Role | Rig move | Card |
  | --- | --- | --- |
  | hook | macro detail pulls out to the full object, with a small live motion | name and a live readout |
  | anatomy | explode, then light each part group as it is named | numbered part index, earlier rows dim |
  | critical detail | reassemble, then push the camera to the detail and fade in an overlay | 2–3 key facts with numbers |
  | law | the overlay drives a displacement | the formula builds term by term, the result counts up |
  | dynamics | periodic drive with a live trace strip and playhead | signed live value plus direction |
  | output | the motion radiates (particles or waves), the camera pulls back | qualitative tags (dense / sparse) |
  | landing | small object plus a comparison of traces | rules (↑ → ↑), then the whole chain as one line |

- **The drawing carries no labels.** Names live in the title, the card and the captions.
- **Layout (9:16):**
  - header at y 132–330;
  - figure at y 330–1290;
  - card at y 1300–1570;
  - nothing of yours below y 1600, which belongs to the captions.
- **Exits** only in the last frame.
- **`SCRIPT.md` format for zh-voice.mjs:**
  - `## Line N — <title> (Frame N)` headings;
  - spoken text on lines indented with 4 spaces;
  - one or two sentences ending in `。`;
  - phrases split by `，；：、`, about 8–14 characters each, so each phrase can become one caption;
  - numbers written as they are spoken (一特斯拉、六牛).
- In each Scene line of the storyboard, tie every state change to a **phrase**, not a guessed second. Exact times arrive in step 4.

### 4 · Voice and timings

Chinese:

```bash
node <skill>/scripts/fit-voice.mjs [--target 60] -- --voice zf_xiaobei [--say "弹波=谈波"]
node <faceless-explainer>/scripts/audio.mjs sync-durations --audio-meta ./audio_meta.json --storyboard ./STORYBOARD.md
```

- `fit-voice.mjs` searches Kokoro's (non-linear) speed until the total lands within ±3 % of the target. The target comes from the storyboard's `duration:`. It leaves the best take in place; record its speed in `SCRIPT.md`.
- For one-off edits, call `zh-voice.mjs` directly. `--reuse` re-times cached audio without resynthesising, and `--only 3,5` redoes only those frames.
- Then read each frame's `words[].start` in `audio_meta.json`. These are the frame-relative phrase starts that every cue in step 6 uses.

English: use faceless-explainer's `audio.mjs` as documented. It transcribes word timings.

### 5 · Rig

1. Copy the templates:
   - `templates/rig.js` → `assets/rig/rig.js`
   - `templates/rig.css` → `assets/rig/rig.css`
   - `templates/preview-rig.mjs` → `tools/preview-rig.mjs`
2. Model the parts:
   - **Turned or axisymmetric parts:** use the quarter-section revolve from `examples/speaker/speaker.js`. Copy `emitRevolved`, `emitRing` and `sectionFaces`.
   - **Prismatic parts:** use `emitBox`.
   - Read the anatomy skill's `references/craft.md` and `references/3d.md` for shading and part detail.
3. Implement every state the storyboard needs: explode, lit, the degree of freedom, and the overlays.
4. Render the preview sheet, screenshot it, and fix the rig until it is clean. The checks and fixes are in [references/rig-contract.md](references/rig-contract.md).

**Gate:** every storyboard state renders cleanly on the preview sheet, and the heaviest state stays under 7.5k paths (the preview log prints the counts).

### 6 · Frames

1. Copy the templates:
   - `templates/frame-shell.mjs` → `tools/frames/common.mjs`
   - `templates/build-frames.mjs` → `tools/frames/build.mjs`
2. Set `RIG` and the `CAM` presets, measured from `bounds()`.
3. Write one spec per frame, using the patterns in `examples/speaker/build.mjs`:
   - all rig and readout state goes inside `R.drive(tl, DUR, fn)`;
   - text and cards use `enter` / `fade`;
   - cue times are the phrase starts from step 4;
   - frame N's end camera and state are copied verbatim as frame N+1's start.
4. Mark each frame `status: animated` in `STORYBOARD.md`.

### 7 · Rebuild and verify

```bash
node <skill>/scripts/rebuild.mjs [--fonts]      # bundle → frames → rig-health → captions(+CJK) → assemble → transitions → tag
npx hyperframes lint
node <skill>/scripts/cue-snapshots.mjs          # one still per narration phrase + frame midpoints
npx hyperframes check
```

- Always rerun the **whole** `rebuild.mjs` after any edit, because the transition injection and the captions tag are lost otherwise.
- Pass `--fonts` when the on-screen copy changed.
- `rig-health.mjs` runs every frame's real driver in a sandbox. It fails on path budget, NaN, non-deterministic renders or a bad camera, so a heavy rig is caught here instead of as a `check` timeout.
- Read the cue contact sheet against the storyboard. Each still is labelled in `cues.json` with its frame and phrase. After a fix, re-snapshot only that frame with `--frames N`.
- Before debugging anything, scan [references/pitfalls.md](references/pitfalls.md).

**Gate:** lint is clean, `check` passes, and the snapshots match the storyboard at every phrase cue.

### 8 · Preview, question, render, deliver

```bash
npx hyperframes preview --background
```

Ask exactly one question: render now, or what changes? After the answer:

```bash
npx hyperframes render --skill=faceless-explainer --quality high --output renders/video.mp4
node <skill>/scripts/deliver.mjs                # duration, contact sheet, frame table → renders/DELIVERY.md
```

Deliver what `deliver.mjs` prints: the MP4 path, the duration, the contact sheet and the frame-id table, so later edits can target one frame.

Also mention once that the preferences were remembered, and relay any line the CLI prints about the desktop app.

## Scripts

| Script | What it does |
| --- | --- |
| `scripts/fit-voice.mjs` | Searches the Kokoro speed until the total length hits the target, keeping the best take |
| `scripts/zh-voice.mjs` | Mandarin narration: synthesises whole sentences, places phrase timings on the real pauses, forces caption group breaks, and writes `audio_meta.json` |
| `scripts/rig-health.mjs` | Samples every frame's real timeline and checks the path budget, NaN, determinism and the camera (exit code 1 on failure) |
| `scripts/cue-snapshots.mjs` | Snapshots the video at every narration phrase cue and frame midpoint, and writes `cues.json` |
| `scripts/deliver.mjs` | Probes the render, builds the contact sheet and writes `renders/DELIVERY.md` with the frame table |
| `scripts/cjk-fonts.mjs` | Downloads Noto Serif SC and Noto Sans SC subsets containing only the characters used |
| `scripts/stage-fonts.mjs` | Copies a preset's Latin font files into `assets/fonts/` |
| `scripts/patch-captions.mjs` | Adds the CJK faces to `compositions/captions.html` |
| `scripts/bundle-rig.mjs` | Inlines the rig CSS into `rig.bundle.js`, which every frame loads |
| `scripts/rebuild.mjs` | The full regenerate chain, in the correct order, with rig-health as a gate |

Templates are **copied** into the project and edited. Scripts are **executed** from the skill folder.
